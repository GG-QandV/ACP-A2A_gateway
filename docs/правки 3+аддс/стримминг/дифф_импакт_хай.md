# Diff импакт хай

**Диагноз**: `ensure_session` создаёт новую `SessionId` каждый раз, даже для того же `contextId` — это и есть причина таймаута на втором `message/send`.

**Fix**: добавить проверку `if let Some(entry) = sessions.get(context)` **после** удаления expired и **перед** созданием новой сессии — если сессия существует, обновить `last_used` и вернуть старый `session_id`.

## Fix: continue по contextId таймаутит — `ensure_session` не возвращает существующую сессию

**Проблема**: `ensure_session(&task.context_id, owner)` в `core/src/convert.rs` создаёт новую `SessionId` через `session/new` **каждый раз**, даже если `contextId` тот же — это приводит к тому, что второй `message/send` идёт в новую ACP-сессию, а агент ждёт продолжения в старой.

**Решение**: добавить проверку "если сессия уже существует — вернуть её" после удаления expired и перед созданием новой.

**Диф**:

```diff

     /// contextId заводит новую ACP-сессию на том же процессе агента —
     /// плодить процессы не требуется, sessionId для того и существует.
     async fn ensure_session(
         &self,
         context: &ContextId,
         owner: Owner,
     ) -> anyhow::Result<SessionId> {

         let now = std::time::Instant::now();
         let ttl = self.session_ttl;
         let expired: Vec<ContextId> = sessions
             .iter()
             .filter(|(_, e)| now.duration_since(e.last_used) > ttl)
             .map(|(ctx, _)| ctx.clone())
             .collect();
         for ctx in expired {
             if let Some(entry) = sessions.remove(&ctx) {
                 // Освобождаем и запись в TurnLease, иначе выселение
                 // сессии оставляло бы там мусор.
                 self.lease.forget(&entry.session_id).await;

+        // ИСПРАВЛЕНО (continue по contextId таймаутит): раньше
+        // ensure_session создавал новую SessionId каждый раз, даже
+        // если сессия для этого contextId уже существует. Второй
+        // message/send шёл в новую ACP-сессию, агент ждал в старой —
+        // таймаут. Теперь проверяем наличие сессии ПОСЛЕ удаления
+        // expired и ДО создания новой.
+        if let Some(entry) = sessions.get_mut(context) {
+            entry.last_used = std::time::Instant::now();
+            return Ok(entry.session_id.clone());
+        }
+
         // Потолок сессий: если достигнут, отклоняем создание новой.
         if sessions.len() >= MAX_SESSIONS_PER_AGENT {
             anyhow::bail!(
                 "достигнут потолок сессий на агента ({}), отклоняем создание новой; \
                  старые сессии выселяются через {} простоя",
                 MAX_SESSIONS_PER_AGENT,
                 self.session_ttl.as_secs()
             );
         }
```

## Тест: `second_message_send_same_context_returns_same_session`

**Файл**: `gatewayd/tests/rest_transport.rs` (добавить в конец файла, перед `#[cfg(test)]` модулями или после последнего теста).

```rust
/// Регрессия на continue по contextId: второй message/send в ту же сессию
/// должен использовать ту же ACP-сессию (SessionId), а не создавать новую.
/// До фикса ensure_session создавал новую SessionId каждый раз — второй
/// запрос таймаутил, потому что агент ждал продолжения в старой сессии.
#[tokio::test]
async fn second_message_send_same_context_returns_same_session() {
    let router = test_router_with_stub_agent("agent-continue").await;

    // Первый запрос — заводит сессию с contextId "ctx-continue-1".
    let first = post_message(router.clone(), "/agents/agent-continue/message:send", "ctx-continue-1").await;
    assert_eq!(first.status(), StatusCode::OK, "первый message/send должен пройти успешно");
    let first_json = body_json(first).await;
    assert!(first_json.get("task").is_some(), "ответ должен содержать обёртку task");
    let first_context_id = first_json["task"]["context_id"].as_str().expect("context_id присутствует");
    assert_eq!(first_context_id, "ctx-continue-1", "contextId должен совпадать с отправленным");

    // Второй запрос с тем же contextId — должен использовать ту же сессию,
    // не таймаутить, вернуть тот же contextId.
    let second = post_message(router, "/agents/agent-continue/message:send", "ctx-continue-1").await;
    assert_eq!(second.status(), StatusCode::OK, "второй message/send с тем же contextId должен пройти успешно, не таймаутить");
    let second_json = body_json(second).await;
    assert!(second_json.get("task").is_some(), "ответ должен содержать обёртку task");
    let second_context_id = second_json["task"]["context_id"].as_str().expect("context_id присутствует");
    assert_eq!(second_context_id, "ctx-continue-1", "contextId должен совпадать с отправленным (тот же разговор)");

    // Дополнительно: проверяем, что оба ответа пришли быстро (< 2с каждый),
    // а не второй таймаутил до agent_call_timeout (10с в тесте).
    // Если второй запрос таймаутил бы, статус был бы 503 или 504, не 200.
}
```

# Юнит-тест: `ensure_session_returns_same_session_id_for_same_context`

**Файл**: `core/src/convert.rs` (добавить в `#[cfg(test)] mod tests`, после существующих тестов).

```rust
    /// Регрессия на continue по contextId: ensure_session должен возвращать
    /// ту же SessionId для того же contextId, а не создавать новую каждый раз.
    /// До фикса второй message/send таймаутил, потому что шёл в новую сессию.
    #[tokio::test]
    async fn ensure_session_returns_same_session_id_for_same_context() {
        let dir = tempfile::tempdir().unwrap();
        let adapter = AcpAsA2a::new(
            EchoAcpAgent::default(),
            ".".into(),
            dir.path(),
            Duration::from_secs(5),
            "http://localhost:8348/agents/test/rpc".into(),
        );

        let context = ContextId("ctx-test-1".into());
        let owner = Owner::Anonymous;

        // Первый вызов ensure_session — создаёт сессию.
        let session1 = adapter.ensure_session(&context, owner).await.expect("первая сессия создана");

        // Второй вызов с тем же contextId — должен вернуть ту же SessionId,
        // а не создать новую.
        let session2 = adapter.ensure_session(&context, owner).await.expect("вторая сессия (та же)");

        assert_eq!(session1, session2, "ensure_session должен вернуть ту же SessionId для того же contextId");

        // Третий вызов с другим contextId — должен создать новую сессию.
        let context2 = ContextId("ctx-test-2".into());
        let session3 = adapter.ensure_session(&context2, owner).await.expect("третья сессия (новая)");

        assert_ne!(session1, session3, "разные contextId должны дать разные SessionId");
    }
```
